# Стиль кода

Как писать GDScript в этом проекте. Обязательно к исполнению, включая закрытые пробы.
Устав (`PURPOSE.md`) говорит, ЧТО делать пробой; этот документ — КАК писать в ней код.
Всё, чего здесь нет, ищется в официальном `GDScript style guide` документации Godot.

## 1. Порядок в файле

```
01. @tool, @icon, @static_unload
02. class_name
03. extends
04. ## докстринг

05. signal
06. enum
07. const
08. static var
09. @export
10. остальные переменные
11. @onready
    ↑ внутри каждой группы: сначала публичное, потом приватное

12. _static_init(), статические методы
13. виртуальные: _init → _enter_tree → _ready → _process → _physics_process → остальные
14. публичные методы
15. приватные методы
16. колбэки сигналов (_on_*)
17. вложенные классы
```

- `@onready` — **всегда последний блок переменных**, вплотную к `_ready()`.
- `_unhandled_input` — это «остальной виртуальный», он идёт ПОСЛЕ `_physics_process`.
- Колбэк сигнала — приватный метод, его место в конце файла, а не рядом с виртуальными.
- Поле класса, используемое только внутри одного метода, — не поле, а локальная переменная.
- Локальная переменная объявляется вплотную к первому использованию.

## 2. Форматирование

Файл: UTF-8 без BOM, переводы строк **LF**, ровно один LF в конце, отступ — **табы**.

Строка — **до 100 символов**, желательно до 80.

**Две пустые строки между функциями.** Одна пустая строка внутри функции — разделить абзацы.

**Перенос выражения — два уровня отступа:**

```gdscript
_camera.rotation.x = clampf(
		_camera.rotation.x - event.relative.y * mouse_sensitivity,
		-limit,
		limit)
```

**Массивы, словари, перечисления — один уровень отступа и завершающая запятая:**

```gdscript
var lines := [
	"speed",
	"peak",
]

enum Kind {
	DUMB,
	BEAM,
}
```

Каждый член перечисления — своей строкой. `enum Kind { DUMB, BEAM }` нельзя.
В однострочном списке завершающая запятая не ставится.

**Длинное условие — в скобках, `and`/`or` в НАЧАЛЕ строки продолжения:**

```gdscript
if (
		event is InputEventMouseButton
		and event.button_index == MOUSE_BUTTON_LEFT
		and event.pressed
):
```

**Один оператор на строку.** Единственное исключение — тернарный:
`next_state = "idle" if is_on_floor() else "fall"`.

Нельзя: лишние скобки (`if (is_colliding()):`), `&&`, `||`, `!` — только `and`, `or`, `not`.

**Пробелы:** по одному вокруг операторов и после запятых, внутри вызовов и индексов лишних нет.
Вертикальное выравнивание пробелами запрещено.

**Кавычки двойные**, кроме случая, когда одинарные экономят экранирование.

**Числа:** `0.234` и `13.0`, не `.234` и `13.`; шестнадцатеричные строчными; разделитель в
больших числах — `1_234_567`.

**Комментарий начинается с пробела** (`# так`), закомментированный код — без (`#print(...)`):
только по этому их и различить. Комментарий пишется своей строкой; в конце строки кода — только
совсем короткий, в несколько слов.

## 3. Имена

| что | как | пример |
|---|---|---|
| файлы | `snake_case` | `camera_rig.gd` |
| классы | `PascalCase` | `class_name OrbitRig` |
| узлы | `PascalCase` | `CameraRig`, `AliveCount` |
| функции, переменные | `snake_case` | `func load_level()` |
| сигналы | `snake_case`, прошедшее время | `signal door_opened` |
| константы | `CONSTANT_CASE` | `const MAX_SPEED = 200` |
| перечисления | `PascalCase`, единственное число | `enum Element` |
| члены перечисления | `CONSTANT_CASE` | `EARTH,` |

Приватное — с одним ведущим подчёркиванием: `_counter`, `func _recalculate_path()`.

**Полные слова.** `acceleration`, не `accel`. `_direction`, не `_dir`. `_camera`, не `_cam`.
`query`, не `q`.

Исключение — **термин предметной области**: `fov`, `hud`, `lod`, `rpm`, `cpa`, `raycast`.
Проверка: произносится ли вслух как слово, а не восстанавливается по буквам.

**Булево имя читается как утверждение.**

- Переменная и свойство — прилагательное, причастие или предлог с существительным:
  `visible`, `aiming`, `on_floor`, `use_sweep_detection`, `auto_bhop_enabled`.
- Метод — `is_` / `has_` / `can_`: `is_aiming()`, `has_method()`, `can_process()`.

Нельзя: `sweep_detection`, `auto_bhop`, `may`, `wants` — по ним не видно, что это булево.
Нельзя и `is_` на свойстве: `is_sweep_detection` не читается.

**Колбэк сигнала — `_on_<источник>_<сигнал>`**: `_on_player_landed`. Для собственного сигнала
источник опускается: `_on_body_entered`.

**Слово не повторяется в имени метода и в его аргументе:** `inventory.add(item)`, не
`inventory.add_item(item)`.

**Имя обязано быть правдой.** Проверка: по одному имени и сигнатуре видно, что вернётся, — и
это совпадает с тем, что возвращается. `_flat(v) -> Vector3` нельзя: читается как предикат.
`_clear(v) -> Vector3` нельзя: читается как «очистить», а означает «обрезать по препятствию».

## 4. Типы

Типизировано всё: параметры, возвраты, поля.

**`:=` — только когда тип написан в той же строке.** Иначе тип пишется явно.

```gdscript
var direction := Vector3(1.0, 2.0, 3.0)    # тип справа, видно глазами
var speed := 0.0                           # 0.0 однозначно float
var health: int = 0                        # 0 неоднозначно, сказано явно
var input: Vector2 = Input.get_vector(...) # из вызова тип не виден

var value := complex_function()            # НЕЛЬЗЯ: какой тип?
var direction: Vector3 = Vector3(1, 2, 3)  # НЕЛЬЗЯ: тип написан дважды
```

**Границы, где вывод молча ломается** — тип пишется руками всегда:

```gdscript
var hit := space.intersect_ray(query)          # Dictionary
var point: Vector3 = hit.position              # доступ в Dictionary — Variant
var bullet: ShootBullet = scene.instantiate()  # instantiate() отдаёт Node
@onready var bar: ProgressBar = $Ui/LifeBar    # get_node() и $ отдают Node
var last: String = names.pop_back()            # элемент Array — Variant
```

Список целиком: `Dictionary`, элемент нетипизированного `Array`, `get_node`/`$`, `instantiate`,
`get_meta`, `Object.get`. Больше нигде тип руками не нужен.

**`$Node as Type` не используем:** при несовпадении типа `as` молча даёт `null` вместо ошибки.

**Имя действия ввода, сигнала и метода — `StringName`:** `&"jump"`, не `"jump"`.

## 5. Возвраты и ветвление

- **Сторожевые условия в начале — можно и нужно, сколько угодно.** Функция отбрасывает случаи,
  в которых ей делать нечего, и дальше идёт ровным телом без вложенности.
- **Нельзя выходить после того, как функция уже изменила состояние.** Если выйти надо
  посередине — состояние меняется одним куском в конце.
- **Нельзя возвращать значение из глубины ветвления.**

## 6. Границы и связность

**Ссылки на узлы идут вниз или приходят снаружи, но не вверх.**
`$Child` — можно. `@export var target_path: NodePath` — лучше всего: зависимость объявлена и
видна в инспекторе. `get_parent()` — **нельзя**: узел перестаёт работать где-либо, кроме одного
конкретного места в одном конкретном дереве.

**Отчёт наверх — сигналом, а не обратным вызовом.** Дёргать создателя через `has_method()` —
это знать его по имени метода, что не лучше, чем знать по имени узла.

**Опрос в `_process` законен для табло.** Сигнал — для СОБЫТИЯ (приземлился, попал), опрос —
для СОСТОЯНИЯ (скорость, дистанция, счётчик).

**`null` заводится только там, где его требует движок.** Поле-ссылка, которое обязано быть
заполнено до первого тика, — приглашение забыть его заполнить: значение передаётся тем же
вызовом, который объект вооружает.

**`@export` — контракт со сценой.** Значение живёт в `.tscn`, а не в скрипте. Переименование
экспортной переменной **молча теряет сохранённое значение**: сцена ищет его по имени, не
находит, откатывает к дефолту скрипта и не печатает ни одной ошибки. Переименование `@export`
и правка всех `.tscn`, которые его переопределяют, — один коммит.

## 7. Комментарии

Комментариев здесь МНОГО, и это осознанно: код проб — учебный материал, и объяснение переживает
пробу наравне с заметкой.

Но тест жёсткий:

> Комментарий имеет право на существование, только если говорит то, чего код сказать не может
> в принципе.

**Проходят:**

- **почему** так, а не иначе — «гравитация применяется безусловно, иначе `is_on_floor()`
  перестанет быть истинным и тело начнёт сходить со склонов»;
- **что пробовали и почему отказались** — «интерполяция физики не включается из скрипта в
  рантайме: узлы, уже стоящие в дереве, остаются с неинициализированным трансформом»;
- **замер** — число, добытое руками: «на 150 м/с пуля проходит 2.5 м за такт, и без свипа ни
  один из пятнадцати выстрелов не попал»;
- **поведение движка**, которое неоткуда узнать по коду — «`physics_frame` приходит ДО
  `_physics_process`»;
- **опасность** — «это смещение нельзя переносить на `SpringArm3D`: он кастует из своего
  начала».

**Не проходят и удаляются:** пересказ кода (`# increase the counter`); имя функции прописью;
комментарий, переставший быть правдой.

**`##` и `#` — разные вещи.** `##` — докстринг: попадает в справку по классу и во всплывающую
подсказку, обращён к тому, кто класс ВЫЗЫВАЕТ. `#` — сноска в теле, обращена к тому, кто
реализацию ЧИТАЕТ. «Почему я так сделал внутри» в `##` не место.

## 8. Числа и величины

- **У физической величины в докстринге стоит единица:** м/с, м/с², Н·с, с, градусы, радианы.
  `punch := 6.0` без единицы — загадка.
- **Границы `@export_range` — документация.** Обе выбираются по смыслу: должны быть значениями,
  которые интересно попробовать руками. Ручка, у которой полезный участок занимает первые три
  процента хода, бесполезна.
- **Число, добытое замером, называет замер рядом с собой** — не «подобрано», а «получено так-то».

## 9. Файлы

`snake_case` для файлов и папок: регистр ломается при экспорте с Windows на регистрозависимые
платформы. Имя файла — это `class_name` в `snake_case`.

Скрипт и сцена называются по КОРНЕВОМУ узлу сцены, если скрипт этой сценой владеет:
`bullet.tscn` с корнем `Bullet` и скриптом `bullet.gd`. Скрипт на узле ВНУТРИ сцены называется
по своему узлу.

`class_name` берёт префикс пробы (`WalkPlayer`, `OrbitRig`, `ShootBullet`): имена глобальны на
весь проект, а имена файлов между пробами повторяются.

Переименование `.gd` — операция на три файла: скрипт, его `.gd.uid` и путь в каждом `.tscn`,
который на него ссылается. На Windows переименование, отличающееся только регистром, git берёт
не с первого раза.
