# 14 — уровень из ручных кусков

| | |
|---|---|
| эталон | Diablo |
| узлы | `Marker3D` как разъём, `Transform3D` как стыковка, поиск с откатом и бюджетом |
| размер | 2 скрипта, 380 строк |
| статус | закрыта 25 августа 2026 |

**Клеток нет вообще.** Атом — кусок: прямоугольник с воротами по краям, ворота это
`Marker3D`, у которого −Z смотрит наружу. Стыковка — две строки, куски щёлкают сами.

## Числа

| ручка | что решает |
|---|---|
| `extent` | половина стороны площадки. **Главная ручка:** от неё зависит, будет ли вообще поиск |
| `target` | сколько кусков просим |
| `budget` | сколько кусков разрешено снять обратно, прежде чем согласиться на меньшее |
| метка ворот | `Vault` берёт только `wide`, а `wide` есть только у `Bridge` |

**Откат детонирует, а не тормозит.** Площадка 60×60, бюджет 20000, по 40 зёрен:

| просим | поставлено | откатов | мс |
|---|---|---|---|
| 10 | 10.0 | 0.2 | 0.6 |
| 20 | 20.0 | 0.2 | 1.5 |
| 30 | 30.0 | 0.6 | 2.6 |
| 40 | 39.5 | **3008** | **155** |
| 50 | 46.8 | 7222 | 391 |

Между 30 и 40 — обрыв в пять тысяч раз, а не «стало медленнее».

**Бюджет покупает всё сразу и дальше ничего.** Просим 40:

| бюджет | поставлено | откатов | мс |
|---|---|---|---|
| 0 (жадно) | 36.5 | 0 | 3.7 |
| 50 | 39.4 | 11.7 | 4.7 |
| 200 | 39.5 | 37.6 | 5.8 |
| 20000 | 39.5 | 3008 | 158 |

В 400 раз больший бюджет даёт +0.1 куска и в 34 раза больше времени.

**Несущий кусок — ветвистый, а не красивый.** Убираем по одному типу, просим 40:

| без чего | поставлено | зёрен недобрало |
|---|---|---|
| `Cross` (4 ворот) | 34.0 | **26 из 40** |
| `Bridge` (единственный `wide`) | 29.6 | 13 |
| `Hall` (4 ворот) | 38.5 | 11 |
| `Vault` (парадная зала) | 39.9 | 1 |

Выкинуть парадную залу незаметно; выкинуть перекрёсток — рушится две трети зёрен.

**Граница превращает рост в поиск.** Без неё уровень растёт в пустоту, и откат не
случается ни разу: 130 кусков, 0 откатов. Всё меняет одна строка `if not
_limit.encloses(rect): return false`.

**Связность бесплатна.** В двенадцатой понадобилась заливка; здесь проверять нечего —
каждый кусок прицеплен к уже стоящему, дерево связно по построению. Способ строить решает,
нужна ли гарантия.

## Только руками

Получается **игровой уровень**, а не план и не схема: по нему понятно, как идти.

Следующий вопрос уходит не вширь, а вглубь — как в эти комнаты попадает разнообразие:
предметы, начинка, всё то, чего в семи кусках быть не может.

## Переносить

- **Кусок = сцена, разъём = `Marker3D`.** Добавить кусок стоит ноль строк кода. То же
  правило, что в реестре эффектов из девятой пробы, только про геометрию. Ворота
  рисуются осями, −Z видно глазом, их можно двигать мышью.
- **Метку вместо типа.** Решатель не знает ни про `Vault`, ни про `Bridge` — он знает про
  `wide`. Третий класс ворот добавляется не трогая раскладчик.
- Границу как проектное решение: площадка не декорация, она определяет, будет ли поиск.
- Низкий потолок на откат. 50 против 20000 — разница в 0.1 куска и 34 раза по времени.
- Мерить библиотеку по ветвлению, а не по тому, что нравится глазу.

## Не переносить

- **Хронологический откат без потолка.** Он выглядит правильным и детонирует. Понадобилось
  больше — не увеличивать бюджет, а перезапускать с другого зерна: дешевле.
- `Array.shuffle()` там, где нужна воспроизводимость: он берёт глобальный ГПСЧ, а не тот,
  которому поставили зерно. Одна эта строка молча убила бы всю воспроизводимость.
- Полагаться на красивый кусок. Один пропавший `Bridge` отрезает `Vault` целиком — один
  кусок может унести с собой целый класс контента.
