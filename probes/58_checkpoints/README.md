# 58 — контрольная точка: игроки, ключ, дверь и таймер

| | |
|---|---|
| эталон | кооперативная головоломка |
| узлы | `CharacterBody3D`, `AnimatableBody3D`, `Marker3D`, файл JSON |
| размер | 5 скриптов, 351 строка |
| статус | открыта |

**Гипотеза: контрольная точка возвращает решаемую комнату.** Вставить ядро в розетку,
включить рычаг и пройти временную дверь вдвоём. Остановиться на любом этапе,
повторить его или загрузить из файла после выхода из сцены.

## Управление

P1: WASD и E, P2: стрелки и ENTER. Действие берёт ядро, отпускает его, вставляет
в близкую розетку или включает рычаг при наличии питания. Пульт: левый стик и X.
Один пульт получает P2, два — обоих игроков; 0 переназначает устройства.

C фиксирует этап в памяти, R восстанавливает его, F5 пишет точку на диск,
F9 читает файл и восстанавливает комнату. N начинает новую комнату, не стирая файл.
2 имитирует сбой и возврат. 1 меняет длительность следующего включения двери: 6 / 12 с.
Подключение питания и завершение комнаты автоматически обновляют точку в памяти;
запись на диск всегда делается F5. При открытии сцены файл сам не загружается.

## Числа и состояния

| этап | игроки после возврата | ядро | дверь и таймер |
|---|---|---|---|
| нет питания | на старте | свободно в исходном месте | закрыта, 0 с |
| питание включено | перед дверью, со стороны рычага | закреплено в розетке | закрыта, 0 с; рычаг снова доступен |
| оба прошли | за дверью на финише | закреплено | открыта постоянно, 0 с |

Это авторские безопасные состояния этапов, а не точная перемотка всех координат.
Запись во время переноса не сохраняет владение; запись во время работы таймера
не сохраняет оставшиеся секунды. Временный ввод очищается, существующие сущности
переставляются без создания копий. Падение игрока или ключа ниже −4 м восстанавливает
всю комнату из текущей точки.

Заканчивающийся таймер не закрывает дверь на игроке: закрытие ждёт освобождения
проёма. Оставшийся перед дверью партнёр может включить рычаг повторно. Завершение
требует обоих игроков на земле в финишной области, одного перехода недостаточно.

Файл — `user://probe58_checkpoint.json`. Формат содержит вид `puzzle58`, версию 1
и имя разрешённого этапа. Сначала записывается временный файл, затем заменяется
основной. Неизвестная версия, чужой вид, неверные типы, обрезанный JSON и отсутствующий
файл оставляют живую комнату и точку в памяти без изменений.

`tools/verify_recovery.gd` проверяет перенос и установку ядра, повторное включение,
истечение таймера в занятом проёме, физическое прохождение двери обоими игроками,
запись/загрузку каждого этапа, загрузку в новой сцене, повреждённые файлы и 20 повторов
без дублирования ключа. Проверки используют отдельный временный файл, не игровой.

## Только руками

Сохраниться с ядром в руках, после установки, посреди таймера и после прохода обоих.
В каждом случае испортить положение игроков и восстановиться. Выйти из пробы,
вернуться и нажать F9. Оставить одного за дверью при истечении времени; убедиться,
что партнёр может снова открыть проход. Записать неожиданные потери прогресса.

Применимость такого подхода зависит от конкретной головоломки: здесь всего три
авторских состояния. Сложные физические конструкции, смена главы и миграция старых
версий сохранений не исследуются. Сбой питания во время записи не моделировался.
