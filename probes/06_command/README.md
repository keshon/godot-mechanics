# 06 — командование сверху и тактическая пауза

| | |
|---|---|
| эталон | Homeworld |
| узлы | `Camera3D` (проекция в обе стороны), `Area3D` как мишень луча, `Control._draw`, `process_mode` |
| размер | 3 скрипта, 469 строк |
| статус | закрыта 21 августа 2026 |

**Пауза — свойство дерева, а не флаг, который все проверяют.** Первая проба, где игрок не
тело в мире, а рука над ним, и от этого меняется весь ввод.

## Числа

| ручка | что решает |
|---|---|
| `unit_count` | 40 читается как отряд, 2000 — как задача про производительность |
| `path_style` | одна нить на приказ или на юнита; см. ниже |
| `dot_style` | кружки против крестиков — пятикратная разница на ровном месте |
| `arrive_radius` | слишком мало — юнит вечно охотится за точкой и не доезжает |
| `pan_speed`, `height` | панорама масштабируется от высоты, иначе вблизи она бешеная |

**Пауза.** За две секунды юнит сдвинулся на 0.0000 м и при этом принял в очередь ещё одну
путевую точку.

**Маркеры путевых точек**, 2000 юнитов, 504 выделено:

| | кадр | из них `_draw` |
|---|---|---|
| точек нет | 3.01 мс | 0.92 |
| кружками (`draw_circle`) | 14.65 мс | 8.00 |
| крестиками, в общей пачке | 2.99 мс | 1.02 |

**Нить на приказ против нити на юнита**, 2000 выделенных:

| | на юнита | на приказ |
|---|---|---|
| 4 точки | 15.04 мс (66 fps) | 5.57 мс (180 fps) |
| 8 точек | 22.59 мс (44 fps) | 5.61 мс (178 fps) |

Важна не четырёхкратная разница, а две правые ячейки: 5.57 и 5.61. **Длина тропы перестала
стоить хоть что-нибудь.**

Объединение линий в пачку не дало почти ничего — 2.99 против 3.07 мс. Привычная оптимизация
здесь не сработала.

## Только руками

С двумя тысячами юнитов кадр проседал, а стоило **снять выделение** — становилось плавно.
Отсюда вытянулась вся история с отрисовкой приказов: симптом виден раньше, чем замер
объясняет причину.

Планирование на замороженном мире работает целиком: выделение рамкой, тропа из нескольких
точек, снятие паузы, исполнение.

## Переносить

- Паузу через `process_mode`, а не через флаг. Дерево само знает, кто замирает.
- Три инструмента перевода экрана в мир и обратно, и понимание, какой когда: плоскость для
  земли, луч для одного объекта, обратная проекция для многих.
- Группировать по **приказу**, а не по совпадению данных. Первая попытка группировала по
  совпадению списков точек и работала ровно до появления построения.
- Сначала померить, потом чинить. Дважды подряд угадал не ту причину: в 04-й думал на
  количество узлов, здесь на количество линий. Оба раза спас замер, а не опыт.

## Не переносить

- Рисование чего бы то ни было на каждый юнит. Двести одинаковых линий на экране — не
  задача на оптимизацию, а ошибка проектирования интерфейса.
- `draw_circle` в цикле. Никогда.
