# 15 — контент как данные

| | |
|---|---|
| эталон | Diablo |
| узлы | `Resource` + `@export` как формат контента, папка как реестр |
| размер | 3 скрипта, 260 строк + 28 файлов контента |
| статус | закрыта 25 августа 2026 |

**Закрытый набор из четырёх глаголов вместо `if type ==`.** Двадцать предметов и восемь
врагов дают сто шестьдесят разных ответов, и ни один из ста шестидесяти нигде не записан.

```
ADD   стат += число
MUL   стат *= число        (всегда после всех ADD, никогда вперемешку)
TAG   тот, кто это держит, бьёт с меткой
VULN  тот, кто это держит, получает ×число от ударов с меткой
```

**Главный замер.** Сгенерировал 200 дополнительных предметов и запустил, не тронув код:

| | было | стало |
|---|---|---|
| предметов | 20 | 220 |
| ответов | 160 | 1760 |
| строк кода | 207 | **207** |
| чтение папки | 10.4 мс | 78.7 мс |

Одиннадцатикратный контент обслуживают те же строки. Цена не исчезла, а переехала во
время загрузки: чтение растёт линейно по файлам.

## Только руками

Видно, что число не задано, а **выведено**: трасса показывает, откуда взялись 69.5, и в
ней нет ни одной строки, которую кто-то писал специально для этой пары.

«Data driven персонажи и инвентарь» до этой пробы были словосочетанием, после неё —
конкретной конструкцией: папка, четыре глагола, метки.

## Переносить

- **Закрытый набор глаголов.** Новая штука стоит ноль строк, новый глагол — пятнадцать
  строк один раз. Проверено на 200 предметах: код не изменился ни на строку.
- **Метку вместо типа.** Урон не знает про ледяного голема; у голема написано, что он слаб
  к огню. То же правило, что с воротами в четырнадцатой пробе.
- **Папка как реестр.** Третий раз подряд — эффекты, куски, предметы. Значит это не приём,
  а способ.
- **Перебор всей матрицы как приёмку.** Столкновение брони и иммунитета (броня оставляет
  щепку в 1 урон, иммунитет не оставляет ничего) нашлось только когда я распечатал все 160
  пар. В data-driven системе баг живёт не в коде, а в **сочетании**, и играми его не найти.
- Умножения после всех сложений, двумя проходами. Это правило РПГ, а не кода: смешаешь
  порядок — и одно снаряжение даёт разные числа в зависимости от порядка надевания.
- Меч и оборотень — один тип. Заголовок, цвет, немного чисел и список эффектов. Резолвер
  спрашивает `kind` один раз; различать их в коде незачем.

## Не переносить

- **Загрузку всей папки разом.** 20 файлов — 10 мс, 220 — 79 мс. Линейно и честно, но на
  тысячах это уже стратегия загрузки, а не `load()` в цикле.
- Веру в то, что типизированного массива достаточно. `Array[DataEffect]` ловит чужой класс
  и не ловит опечатку в значении: `stat = "powr"` пройдёт молча. Нужен проход-валидатор по
  всему контенту, как заливка в двенадцатой пробе.
